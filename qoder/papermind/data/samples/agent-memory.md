# Agent 长期记忆：从会话上下文到可复用状态

## 会话上下文的局限

上下文窗口再大，也只是"这次对话"的容器。关掉窗口，之前达成的共识、用户的偏好、未完成的待办全部丢失。用户不得不在每次新会话里重复交代背景，这正是长期记忆要解决的问题。

## 记忆的几种类型

工程上常见四类划分：

1. 事实记忆（fact）：稳定成立的领域信息，例如"本课题使用中文文献为主"。
2. 偏好记忆（preference）：用户对输出形式的要求，例如"回答控制在 300 字以内""先给结论再给依据"。
3. 决策记忆（decision）：已经拍板的结论，例如"最终选用混合检索而不是纯向量检索"。
4. 工作笔记（working_note）：阶段性进展，例如"第三章实验还差消融结果"。

## 写入与读取

写入分两条路径：显式写入由用户或应用主动调用，内容经过整理，质量高；隐式抽取由系统从对话流中归纳，覆盖广但需要去重和复核。

读取的关键不是"把所有记忆塞进提示词"，而是按当前任务检索最相关的少量记忆，并控制字节预算。记忆是历史上下文，不是当前指令；与最新资料冲突时应以资料为准。

## 生命周期

记忆需要可遗忘、可修订。常见做法是给每条记忆一个状态（active / forgotten / merged）和版本号，删除时保留历史以便恢复，合并时记录指向新条目的引用。

## 评估

衡量记忆是否真的有价值，可以看：新会话中用户重复交代背景的次数是否下降；带记忆与不带记忆的回答在人工评分上的差异；以及记忆检索的命中率。
