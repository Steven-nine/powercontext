# RAG 系统的评测方法笔记

## 为什么不能只看最终答案

RAG 是一条流水线，最终答案差，可能是召回没找到，也可能是找到了但模型没用上。只评端到端分数，无法定位问题。因此要把评测拆成检索质量和生成质量两层。

## 检索层指标

- Recall@K：正确片段是否出现在前 K 条结果里，最直接反映召回能力。
- MRR：第一个正确片段排名的倒数均值，衡量排序质量。
- nDCG：考虑多级相关性时的排序指标。

构造评测集时，需要人工标注"这个问题应该由哪几个片段回答"。片段粒度变化后，标注要同步更新。

## 生成层指标

- 忠实度（faithfulness）：答案中的每个论断是否都能在检索片段中找到支撑。
- 答案相关性：答案是否切题，不答非所问。
- 引用准确率：标注的 [n] 是否真的支撑对应句子。

忠实度和引用准确率可以用大模型做裁判，但必须人工抽查校准，否则会出现裁判模型自洽的假高分。

## 工程建议

1. 先固定语料和切片策略，再比较不同 embedding 或融合方式，否则变量太多。
2. 保留失败样本集，每次迭代后重跑，观察是否引入回归。
3. 记录每次查询的检索轨迹（关键词、各路召回、融合名次），出问题时才能复盘。
4. 用真实用户问题做测试集，比用论文里的样例更接近实际分布。
