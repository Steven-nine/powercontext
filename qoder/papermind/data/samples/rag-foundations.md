# 检索增强生成（RAG）的基本流程

## 问题从哪里来

大语言模型的知识被冻结在训练语料里，遇到私有文档、最新论文或企业内网资料时，只能靠参数记忆去猜。RAG（Retrieval-Augmented Generation）的核心思路是把"记忆"外置：先检索，再生成。

## 两个阶段

RAG 系统可以拆成离线索引和在线问答两条链路。

离线索引：文档解析 → 文本切分（chunking）→ 向量化（embedding）→ 写入向量库，同时保留标题、章节、页码等元数据。

在线问答：用户问题 → 问题向量化 → 向量库召回 Top-K 片段 → 把片段拼进提示词 → 模型生成带引用的答案。

## 为什么引用很重要

生成模型的输出不可直接信任。让模型在答案里标注片段编号，用户才能回到原文核对。工程上通常要求：答案里的每个关键论断都能对应到至少一个检索片段，否则视为无依据陈述。

## 常见失败模式

1. 召回不到：切片过大导致语义稀释，或 embedding 模型与领域不匹配。
2. 召回了但没用上：提示词没有约束模型"只依据材料回答"。
3. 用上了但答偏：多段材料互相矛盾，模型自行取舍而未说明冲突。
4. 上下文超长：Top-K 设得过大，关键片段被淹没在噪声里。

对应的缓解手段分别是调整切片粒度与混合检索、强化系统提示词、显式要求标注冲突、以及加入重排序（rerank）压缩候选集。
