# 混合检索：向量、全文与 RRF 融合

## 两种召回的互补性

向量检索（dense retrieval）把句子映射到连续空间，擅长处理同义改写和语义相近但用词不同的情况。例如用户问"如何让回答有出处"，向量检索能召回标题为"引用与可追溯性"的段落。

全文检索（sparse / lexical retrieval）基于词项匹配，擅长精确命中专有名词、型号、缩写和数字。用户搜"text-embedding-v3"或"RRF k=60"时，全文检索几乎不会漏，而向量检索可能因为低频 token 被稀释而失手。

两者的失效场景恰好互补，因此工业系统普遍采用混合检索。

## 融合策略：RRF

Reciprocal Rank Fusion（RRF）是最常用的无参数融合方法。对每个候选文档 d，计算：

score(d) = Σ 1 / (k + rank_i(d))

其中 rank_i(d) 是文档在第 i 路召回中的名次，k 是平滑常数，常用 60。RRF 只使用名次、不使用原始分数，所以不需要把余弦距离和 BM25 分数归一化到同一量纲，实现简单且鲁棒。

## 实现要点

1. 两路召回各自保留较大的候选集（如各 20~50 条），融合后再截断到最终 Top-K。
2. 结构化过滤条件（年份、类型、标签）应同时下推到两路召回，避免先过滤后融合造成的候选不足。
3. 中文全文检索需要合适的分词器，IK 分词对中英混排的技术文档效果稳定。
4. 融合分数只用于排序，不建议直接当作相关性阈值使用。

## 什么时候不该用混合检索

如果语料全是短文本且查询以关键词为主，纯全文检索更便宜；如果查询全是自然语言长句且语料术语稀疏，纯向量检索也够用。混合检索的价值在两类查询并存的真实场景中才明显。
