# 中文 Embedding 模型选型笔记

## 维度与成本

常见中文 embedding 模型的输出维度在 512 到 1536 之间。阿里云通义 text-embedding-v3 默认输出 1024 维，并支持通过 dimensions 参数降到 512 或 768。维度降低能显著减少索引体积和检索延迟，但对语义区分度有轻微影响，需要用评测集验证。

## 距离度量

文本 embedding 通常已归一化，使用余弦距离（cosine）最稳妥。若用内积（inner product），必须确保入库和查询时都做了相同的归一化，否则排序会失真。L2 距离在归一化向量上等价于余弦距离的单调变换，也可以使用，但排序阈值需要重新标定。

## 中英混排

技术文献常常中英混排。选择模型时要看它在中文技术语料上的表现，而不只是通用中文榜单。实际测试中，术语缩写（如 RAG、RRF、HNSW）如果被切碎，检索效果会明显下降，这时混合检索里的全文通道能补足。

## 批量与限流

在线服务通常限制单次请求的文本条数和总 token 数。入库时应按批提交（例如每批 10 条），并对失败批次做重试；查询时只提交一条文本，延迟敏感。

## 换模型的代价

更换 embedding 模型意味着向量空间变了，历史向量全部失效，必须重建索引。因此集合创建时就要把模型名和维度记录下来，作为索引的元信息，避免误用。
