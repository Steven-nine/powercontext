# 验证样例：SPEC-SHIP-002 偏远地区运费

本文件给出**可完整复现**的验证样例：任务、有效规格、初始数据、操作步骤、预期结果与重置方法。

---

## 1. 任务描述

> **要改什么**：在订单结算业务工程 `shopcalc` 中实现规格条目 **SPEC-SHIP-002 偏远地区运费**——
> 收货地区属于 **新疆 / 西藏 / 内蒙古** 的订单，运费固定为 **¥20.00**；
> 该规则**优先于** SPEC-SHIP-001 的「满 ¥99 免运费」规则，即使商品金额满 ¥99 仍收取 ¥20 运费。
> 运费金额不计入商品金额，也不参与免运费门槛的计算。

> **哪些原有行为必须保持**：
> 1. 普通地区：优惠后商品金额 ≥ ¥99 免运费（¥0.00），否则 ¥8.00；
> 2. 免运费门槛只看**优惠后商品金额**，与运费无关；
> 3. 优惠券规则（SPEC-CPN-001）与会员折扣（SPEC-MEM-001）行为不变；
> 4. 订单应付金额 = 优惠后商品金额 + 运费（SPEC-SETTLE-001）。

**任务编号**：`ship-002`（用于关联 PowerContext 中的 Scope）

## 5. 操作步骤

### 5.1 一条命令（推荐）

```bash
cd minimax
export MINIMAX_API_KEY=<你的 key>
python scripts/run_verification.py
```

脚本按下列顺序执行：

| 步 | 动作 | 预期 |
|---|---|---|
| 0 | 重置：清空 seekdb、删除 PowerContext 状态库、把 `business/` 还原为 `baseline/business/` | — |
| 1 | 修改前跑测试：目标测试 / 回归测试 | 目标测试退出码 ≠ 0；回归测试退出码 = 0 |
| 2 | 导入 v1.1 规格 + 全部代码 + 全部测试到 seekdb | 8 份资料写入并建索引 |
| 3 | 组装上下文 → 导入 v1.2 规格 → 重新组装上下文 | 旧上下文**不含** `SPEC-SHIP-002`；新上下文**含** `SPEC-SHIP-002` |
| 4 | 把上下文交给 MiniMax，解析 unified diff 并应用 | 补丁应用成功，测试全部通过 |
| 5 | 修改后跑测试：目标 / 回归 / 全量 | 三个退出码均为 0 |
| 6 | 写入 PowerContext 状态 → **另起进程**读回 → 用读回的状态组装新上下文 | 读回退出码 = 0，上下文含状态 |
| 7 | 产出差异与快照，并记录数据库查询与开发记录 | `artifacts/` 齐备 |

   判定目标 / 回归，判定规则写在 `sddctx/context.py` 的 `role` 字段中。

   此时使用的是已归档的 `artifacts/diff/minimax_generated.patch`。
4. MiniMax 重新生成补丁时措辞可能不同（不要求逐字一致），验收以**测试结果**为准。
