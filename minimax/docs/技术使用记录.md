### 1.6 迭代过程（可选 `--max-attempts` 观察）

开发助手循环支持失败反馈重试：补丁应用失败或测试未通过时，**还原工作区**，
把错误信息回灌给 MiniMax 重新生成。早期调试中确实出现过因模型给出的 hunk 行号有偏差
而导致的"上下文不匹配"，模块据此实现了按上下文内容就近定位区块
（`sddctx/diffutil.py::_locate_hunk`，对应单元测试 `test_apply_unified_diff_locates_hunk_when_line_numbers_are_wrong`）。
最终一次调用即通过。

> 说明：开发过程中多次重跑，MiniMax 生成的补丁措辞略有不同（例如 `Decimal("20")` 与
> `Decimal("20.00")`、常量的注释顺序、`frozenset[str]` 类型标注），**均满足规格且测试全绿**。
> 提交仓库中保留的是最后一次验证运行的产出。

## 二、数据库（seekdb / OceanBase）使用记录

### 2.1 部署与连接

| 项 | 值 |
|---|---|
| 产品 | seekdb `1.4.0`（`SELECT VERSION()` → `5.7.25-OceanBase seekdb-v1.4.0.0`） |
| 部署位置 | WSL2 `Ubuntu-24.04`，systemd 服务 `seekdb.service`，`--port=2881` |
| 协议 | MySQL（`pymysql` 纯 Python 驱动） |
| 连接串 | `mysql://root:@127.0.0.1:2881/sdd_ctx`（模块自动建库） |
| 数据库 | `sdd_ctx`，字符集 `utf8mb4` / 排序规则 `utf8mb4_bin` |
| 客户端代码 | `minimax/sddctx/store.py` |

### 2.2 数据模型（由模块自动创建）

| 表 | 作用 |
|---|---|
| `sdd_doc` | 资料全文：`doc_id` / `kind`(spec/code/test) / `path` / `version` / `content` / `revision` / `content_sha256` |
| `sdd_doc_revision` | 修订历史：同一 `doc_id` 每次内容变化追加一行（含版本与内容哈希） |
| `sdd_spec_entry` | 规格条目：`entry_id`（如 `SPEC-SHIP-002`）/ `title` / `body` / `revision` |
| `sdd_symbol` | 代码符号：`symbol_id` / `name` / `kind` / `signature` / `line_start` / `line_end` / `cited_specs` |
| `sdd_term` | 倒排索引：`term` / `doc_id` / `field` / `tf`，主键 `(term, doc_id, field)` |

### 2.3 数据库实际承担的工作

1. **存储**：规格、代码、测试的**全文**写入 `sdd_doc.content`，代码符号写入 `sdd_symbol`，
   规格条目写入 `sdd_spec_entry`。
2. **索引**：写入时按「英文按标识符切分 + 中文按字切分」建立倒排索引 `sdd_term`，
   并按 `field` 区分规格 / 规格条目 / 符号 / 代码 / 测试，供字段加权 BM25 使用。
3. **检索**：上下文组装执行两轮 SQL 检索（倒排索引命中 + 文档频次统计），
   检索结果**直接决定**上下文中出现哪些规格条目、哪些代码符号、哪些测试。
4. **版本可见**：规格重新导入后 `revision` 自增，`sdd_doc_revision` 保留 v1.1 / v1.2 两条历史。

### 2.4 查询记录

完整 SQL 与返回行见 **`artifacts/logs/db_queries.md`**，摘要：

| 查询 | 返回 |
|---|---|
| `SELECT kind, COUNT(*) FROM sdd_doc GROUP BY kind` | `code=4`、`spec=1`、`test=3` |
| `SELECT entry_id, title, revision FROM sdd_spec_entry` | 6 条规格条目，`revision=2`（含 `SPEC-SHIP-002`） |
| `SELECT t.term, t.doc_id, t.field, t.tf FROM sdd_term WHERE t.term IN ('shipping_fee','运','费')` | 命中 `business/shopcalc/pricing.py`（`field=code` / `field=symbol`）与 `business/tests/test_shipping.py`（`field=test`） |
| `SELECT s.name, s.kind, s.line_start, s.line_end, s.cited_specs, d.path FROM sdd_symbol s JOIN sdd_doc d …` | 列出全部代码符号及行号、引用规格 |
| `SELECT doc_id, revision, version, content_sha256 FROM sdd_doc_revision` | `settlement-spec` 的 `revision=1/version=1.1` 与 `revision=2/version=1.2` 两条历史，哈希不同 |

### 2.5 检索结果确实被用于上下文

`artifacts/logs/context_final.json` 中每一条规格 / 代码 / 测试都带有
`source.path`（数据库中的 `sdd_doc.path`）与 `score`（BM25 得分），
模块在组装时会逐条校验来源文件在工作区**真实存在**，否则直接失败。

## 三、PowerContext 使用记录

### 3.1 接入方式

| 项 | 值 |
|---|---|
| 接入方式 | **Python SDK**（`powercontext[builtin]==1.2.0`） |
| 使用接口 | `open_builtin_runtime()`、`runtime.scopes` / `runtime.sources` / `runtime.memory` / `runtime.work` / `runtime.handoff` |
| 持久化后端 | PowerContext 内置 relational 后端（SQLite 文件） |
| 状态库文件 | `SDDCTX_STATE_DB`，默认 `D:\DeepSeek缓存\minimax-sdd\state\powercontext.db` |
| 客户端代码 | `minimax/sddctx/state.py` |

> 为什么不用 `kind=oceanbase` 直连 seekdb：PowerContext 的 OceanBase 后端要求
> `SHOW VARIABLES LIKE 'ob_compatibility_mode'` 返回 `MYSQL`，而 seekdb 1.4.0 **不提供该变量**
> （实测 `SHOW VARIABLES` 共 708 个变量，无 `ob_compatibility_mode`），因此该后端会拒绝连接。
> 本作品据此把**工程资料与检索索引**放在 seekdb，把**任务状态**放在 PowerContext 的
> SQLite 后端，两者职责分离、互不干扰。

### 3.2 状态结构

| 载体 | 写入内容 | 读回接口 |
|---|---|---|
| **Scope** | 每个 `task-id` 一个 Scope，用 `ScopeBindingKey(integration="competition", kind="minimax-sdd", external_id=task_id)` 绑定 | `runtime.scopes.resolve_binding()` |
| **Work contract** | 目标、范围（待改文件）、完成判据、事实 | `runtime.work.for_scope().create_contract()` |
| **Memory 条目** | `completed`（已完成事项）、`todo`（待办事项）、`verification`（已有验证结果）、`decision` | `runtime.memory.for_scope().remember()` / `.list()` |
| **Handoff 里程碑** | 每个阶段的检查点（已选规格 / 已选符号 / 测试结论 / 下一步） | `runtime.handoff.for_scope().commit()` / `.continue_latest()` |
| **Task outcome** | 本次结论 `succeeded` 与逐项检查（passed / failed / details） | `runtime.work.for_scope().record_outcome()` / `.continuity()` |
